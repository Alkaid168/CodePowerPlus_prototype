# 单题录入与人工审核：2026-10-04 已授权范围与实现

目标：团队或教师录入学校 OJ 等来源的题目，提供可核对的知识标签和难度评分。
学生使用整理后的题目；本阶段不新增账号权限、私有 OJ 对接或文件批量导入。

## 工作流程

1. 在题目录入与分析页面粘贴标题和 Markdown 题面；来源链接、参考题解和参考代码可为空。
2. 选择保存并分析，或者保存后手工标注。模型失败时题目已保存，重试先保存最新输入，并沿用原编号。
3. 查看分析，必要时保存手工标注。每次保存生成待审核新版本，结果页面自动刷新。
4. 在独立审核队列核对题面、参考材料和解题思路；通过、驳回或修改后通过。
   可纠正标签、各标签证据和置信度、整体置信度、800–3500 难度、难度理由、解题思路。
5. 已有题目可修订并保存。任何题目信息变化都会递增版本（包括来源链接），原分析显示需要更新。
   为修订后的题目重新分析或保存手工标注，再审核；历史分析及审核记录继续可查。

## 数据约束

- 分析不可变，输入快照包括标题、题面、来源、参考题解和代码；原学习记录不倒改。
- 存储版本 3 通过补列迁移兼容旧库。旧记录没有输入快照时明确显示缺失。
- 修改题目要求 expected_revision；浏览器手工标注也携带它。早期接口调用者暂允许省略手工版本参数。
- 模型调用期间若题目被修改，拒绝保存旧输入结果，返回 409。审核旧版本也返回 409。
- 参考代码仅作为文本，不执行。模型输入不包含来源平台或官方评分；Codeforces 风格只是数值标尺。
- 系统提示词 problem-analysis-v5 已在实现前完整展示，源码位于 app/services/analysis.py。

## 验收与限制

隔离数据库验证输入往返、无变化保存、冲突编辑、过期分析排除、模型期间修订、审核纠正与事务回滚；
浏览器验证失败恢复、手工结果刷新、审核保存、布局与窄屏。合成测试题仅用于功能验收。

功能验收不能证明模型分析可靠。下一阶段需要团队提供 20–30 道熟悉解法的学校真题逐题核对；
题库扩充和难度校准仍待开展，批量导入、带反馈重分析及多解法进入画像规则暂缓。
