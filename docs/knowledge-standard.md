# 知识体系标准（题目标签词表）

版本 2026.09.9，共 345 个节点：9 个 L1 领域、151 个 L2 节点、185 个 L3 节点，其中 313 个叶子知识点各带一段 50–200 字的中文介绍。结构取自 OI Wiki（oi-wiki.org）的栏目导航，去掉栏目简介、工具软件、语言基础等不能作为题目标签的内容。

## 它是什么

知识体系只回答一个问题：**这道题考什么**。它是一份标签词表，供三处使用：题目分析的标签选择与校验、能力画像的汇总口径、题目推荐与学习路径的目标选择。因此节点必须是“一道题可能被标上的东西”。

## 节点与层级

分支节点只有四个字段：`id`、`name`、`level`、`parent_id`；叶子知识点额外带一个 `summary`（50–200 字的中文介绍，用于界面展示与学习参考，不参与标注）。仍然没有难度、典型算法、学习目标、常见误区、例子、参考资料与前置关系。

- `level=1`：L1 领域（基础算法、搜索、动态规划、字符串、数学、数据结构、图论、计算几何、杂项）。领域只用于聚合统计，不能作为题目标签。
- `level=2`：二级节点。**既可以是分支**（下面挂 L3，如 数学 → 数论 → 素数），**也可以本身就是知识点**（没有下级，如 数学 → 快速幂）。
- `level=3`：三级知识点（如 数学 → 组合数学 → 容斥原理）。
- 不建 L4；实现细节写进题目分析的证据句，不拆成新节点。

`id` 由 OI Wiki 的栏目路径推导（路径分隔符换成 `.`），小写、稳定、唯一；`name` 是全树唯一的标签名，避免同名标签产生歧义。

## 标注规则

- AI 与人工都只能从当前版本的 L2/L3 中选 ID，不能创造标签或改名字。
- 主标签至少一个；同一 L2 分支**可以**有多个主标签（一道题既能用树状数组也能用线段树，就都标上），
  但不要同时选择祖先和后代（例如“数论”与“素数”二选一）。
- 每个标签都要有题面或解法中的具体证据句，以及 0..1 置信度。
- 题目分析保存 `taxonomy_version`；版本变化后需要显式迁移或重新标注，不能混用两版 ID。

## 维护规则

- 新增节点要有题目需求；先问“会有题被标上它吗”，答案是否定的就不要加。
- 目录版本化：改动后升版本号，并在 `data/taxonomy_versions/` 留快照。
- 删除节点就从新版本移除，并在 `PROJECT_MEMORY.md` 记录原因；旧分析保留自己的 `taxonomy_version`，不会被新版本强行解释。
- 禁止用脚本批量生成“只有名字、没有题目需求”的空壳节点（2026.09.4 的 301 个占位节点就是反面例子）。

## 代码接口

`Taxonomy` 提供 `data`、`version`、`nodes`、`validate`、`get`、`children`、`tree`、`search`、`allowed`、`ancestors`、`branch`、`describe`、`validate_assignment`。JSON Schema 使用 Draft 2020-12 严格校验字段；业务校验检查 ID 唯一、层级连续、父节点存在。`allowed` 只接受 L2/L3。

HTTP：`GET /api/knowledge/tree` 返回 `{version, tree}`；`GET /api/knowledge/search?q=&level=` 返回 `{version, items}`；`GET /api/knowledge/{id}` 返回节点、`ancestors` 与 `children`。

工具：`scripts/taxonomy_tool.py` 支持 `validate`、JSON/CSV `export`/`import` 与带显式映射的 `migrate`（默认 dry-run，`--apply` 原子写入）。

## 目录维护工具

`scripts/check_notes.py <assignment.json> <notes.json>` 用来校验一批知识点介绍的键集合、长度（50–200 字）、重复段落与套话，适合批量补写或修改介绍时先自查。

### 搜索规则

- 搜索同时匹配中文名称和英文 ID。
- 匹配不区分大小写；空格、点、横线、斜杠和括号会归一化为空格后比较。
- 因此 `DFS`、`dfs`、`shortest path`、`shortest-path`、`binary exponentiation` 都可命中对应节点。
- 前端知识树使用缓存数据按同样规则本地过滤，不额外请求搜索接口。
