# 用户画像模块重写设计

日期：2026-10-24。目标是替换旧画像前后端，构建总分加十个L1能力域、冷启动自评、证据可信状态和后续IRT更新的完整边界。

## 已确认要求

- 十一个指标：总分、语法基础、算法基础、搜索、动态规划、字符串、数学、数据结构、图论、计算几何、杂项。
- 语法展示分范围为0–800；九个算法域使用CF风格难度坐标，不设4000硬上限。
- 语法阶段的总分等于语法分；算法阶段的语法分固定展示800，总分从算法九域派生，九域全为800时总分为800。
- 分数可以上升或下降。练习难度偏移200、动态能力方差扩散已在独立评分原型中实现，继续沿用该候选响应曲线。
- 新注册用户应可填写现状和训练目标。自报初值属于弱先验/暂定信息，不应伪装成提交证据；无证据、真实0分和自报值应可区分。
- 旧画像前后端不作为新产品实现基线；外站采集和图谱现已交付，但外站题目尚未可靠映射到项目知识标签及项目统一难度。

## 第一阶段设计

1. 用一个轻量冷启动问卷收集经验档位、常用语言、训练目标及目标知识域。档位提供的800/1200/1600是用户此前给出的候选初值。后端持久化其来源为自报，并保留宽不确定性；目标只影响辅导方向，不加减能力分。
2. 新画像页展示总分和十个L1域、当前阶段、估计来源和证据状态。自评起点清楚标“暂定”，没有实际可归属证据时显示“待验证”。
3. 新后端画像资源和隔离SQLite表单独存放画像设置及未来有效机会；不自动把跨站提交复制为学生能力证据。
4. 先实现阶段状态：`syntax`或`algorithms`。初始问卷选择阶段；达到语法阶段边界、退出阶段及长期转换规则以后续证据处理切片明确实现，不能让一次错误提交把算法选手降回初学者。
5. 总分暂用均衡型RMS候选：算法阶段 `800 + sqrt(mean(max(r_k - 800, 0)^2))`。它保留用户提出的800锚点、对专项高分比算术平均更敏感且无上限。聚合只从九域状态派生，不将同一份题目证据重复独立加到总分。此公式是可配置版本化的产品选择，不是IRT定理或真实效度结论。

## 证据边界

画像事件必须是已整理的独立作答机会，至少包含题目难度、时间、练习/比赛条件、成功结果和实际涉及的能力域。多种替代方法按代码确认所用方法；联合必要知识可同时支持多个域，但一次题目机会不会因此被复制成多次独立历史。WA等非AC只有在事件被定义为有效考察机会后才进入模型；同题重试不拆成多场测试。

第一阶段不自动将采集库的2013条外站记录打进评分。它们当前没有可靠项目难度、知识点和实际解法归因契约；外站用户身份也不能当作应用账号认证。画像证据端点上线前，只有来源明确且已核验的方法和题目元数据可以使用。

## 本阶段范围

- 删除错误共享记录中的“本画像对话是总控”角色声明，保留项目总体阶段排序。
- 实现画像设置存储、冷启动读写契约、十个L1映射和派生总分单元逻辑。
- 用新的能力画像页面替换旧的标签命中率表，支持查看暂定状态和修改冷启动设置。
- 补充独立测试、临时数据库HTTP验证和实际浏览器布局/交互验收。
- 画像证据账本、可靠的逐题/代码归因、IRT后验接入和真实数据校准继续分阶段推进；不宣称本阶段完成画像全链路。

## 风险与限制

- 初始档位数值尚未由真实训练数据校准，UI必须显示自评来源和不确定性。
- RMS体现“均衡竞赛能力同时容纳偏科优势”的产品取向，用户可根据试用体验调整；不能宣传为Codeforces官方总分。
- 目前没有应用身份认证；`user_id`只是本地原型学习者键，不是安全边界。
