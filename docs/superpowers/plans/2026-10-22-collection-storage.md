# 采集与存储加固实施计划

**授权：** 用户已同意 SQLite 存储方向并要求继续开发；在本对话直接实施，不提交其他模块的既有改动。
**目标：** 源码只存一份、用户配额原子生效、旧库可迁移、删除与备份可测试；扩展支持分批上传及明确卸载边界。
**设计依据：** `docs/collection-storage-design-2026-10-21.md`。

## 1. SQLite 存储

- [x] 新建 `app/collection_storage.py`，从 `app/collection.py` 分离存储实现；保留现有导入/查询调用契约。
- [x] 提交元数据改显式列；源码存 `(user_id, hash)` 唯一 BLOB，批次只存摘要/覆盖范围/计数；观察记录仅保存无源码元数据，最多20次实际变化。
- [x] 默认120/150 MiB提醒/硬上限，可通过环境变量修改；逻辑字节数包括元数据、唯一源码、收据、观察及固定行开销。配额计数与导入同事务，重试不计费，超限整批回滚。
- [x] SQLite WAL、外键、busy timeout；事务迁移旧三表，迁移前用 backup API 生成独立备份；不访问正式学习库。
- [x] 先写测试并观察失败，再验证去重、回滚、跨用户、迁移、并发配额、删除后的空间计量。

## 2. API 与运维

- [x] GET `/api/collection/storage` 返回本人四站合计用量。
- [x] DELETE `/api/collection/submissions` 仅接受专用 manage 令牌与明确确认，按令牌平台/账号删除；普通导入令牌不能删除。
- [x] 备份/恢复命令只创建新文件；恢复验证 integrity/schema，禁止覆盖现有库。
- [x] 存储超限返回结构化413；SQLite忙返回503；数据库错误不得泄露源代码。

## 3. 扩展与使用流程

- [x] 上传计划用IndexedDB小页生成，上传只读取当前批次，保留旧上传断点兼容；排除上传中重复点击/重同步竞态。
- [x] 配额不足/令牌过期给中文说明，确认服务端逐批接收后才提示成功。
- [x] 修复已发现的重新同步引用未定义变量；导出与上传操作期间固定任务并避免并行修改。
- [x] 说明“安装→正常登录OJ→采集→预览→导出/上传→确认→可卸载”；仅有本地缓存时不能卸载，重新同步需重新安装。
- [x] Node、隔离Edge、全套pytest和5,000条合成容量/并发/恢复实测；更新长期记录并打包。
