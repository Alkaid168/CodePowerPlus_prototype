# 模块v8：从错例到可验证的数据流

2026-10-17更新：v8首测已收到完整人评并完成揭盲诊断，见[最终分析](v8-first-test-analysis.md)。同题难度误差有所改善，语义审查存在严重漏检，仍为实验基线；下述流程保留为实现说明。

## 问题与判断

v7首测算法9/24驳回（37.5%），版本状态为非成品。标签与解法不一致有具体输出证据；“先写标签导致后面解法与标签脱节”仍是机制假设。评分偏低与模型熟悉模板、低估新生学习门槛有关，是待人评验证的解释，不能仅靠模型自检确认。

[研究报告](v8-rating-research.md)核对六项官方资料/论文，借鉴显式评价标准、结构化审查和独立留出样本的做法，不移用论文准确率，也不把公开新选题称为模型未见题。

## 已实现

1. 第一阶段只生成可审核解法及方法—知识映射，不输出难度；完整约束、自然解法与合理替代方案仍需说明，保留多个有效算法标签。
2. 第一阶段方法知识点并集必须等于主辅标签；同时执行词表合法性、证据、语法/算法互斥校验。能检查模型声明的一致性，不能自动证明算法正确或发现所有语义漏标。
3. 第二阶段接收题面、已验证方案和选中知识点；分别说明知识、建模、证明与实现门槛后整体评分。等级保留100–3500及现有分档，不根据旧错题人为加固定分数，不使用过河卒等本次开发反馈作为具体分值锚题。
4. 第二阶段发现实质矛盾退回第一阶段；格式/一致性错误携带被拒输出与具体错误限次修复。多次失败明确失败，不补造可入库结果。
5. 成功分析保存每次逻辑调用的响应model、用量、时延、可见JSON和修复记录。整体置信度取两阶段自报较小值，仍未校准，不能据此免审。SDK传输重试与逻辑调用不是同一计数，缺失网络请求的实际费用不可凭空补算。

完整系统提示词先展示，再分别归档于 `app/prompts/problem-analysis-v8-solve.txt` 和 `problem-analysis-v8-grade.txt`。原v7实现另存只读历史副本；旧批次不改写。

## v8首测

采用全部9道旧驳回题和11道不同算法的新题。新增题从官方页核验技术题意、数据范围、运行限制和13组官方样例；模型只接收题面及原有参考资料，不接收平台标签、链接、旧分数或本轮人工目标分。

实验协议、实现、提示词、词表及输入在调用前冻结哈希，预测先完成并在工作区外封存；公开哈希承诺后才发空白人工表。模型输出不写正式题库，不替用户审核，不在人工提交前展示分数或分布。

比较工具已实现完整20项评分校验、原始链接一致性校验、封存校验、逐题有向/绝对差和全部20/回归9/新增11分组指标。模型封存阶段没有人工结果；后续人评完成的误差统计与语义复核见最终分析，不将误差窗口比例当作准确率或驳回率。

9道旧题已经被双方接触且参与开发反馈，公开链接可能显示原站评级，因此本次是带回归组的遮蔽模型预测评测，不是严格双盲实验。单人20题也不能证明生产泛化；人评完成后再分析错例、决定后续版本与独立学校题验证。
