# v8首测：预测前冻结的评测协议

本协议在模型调用与人工评分之前制定。模块v7非成品；v8仍为实验版本，开发完成不等于评测通过。

## 样本和盲法

- 固定20题，不按模型表现筛换：v7首测全部9道最终驳回题作为回归组，另11道已核验原始链接/完整技术约束/官方样例的不同算法题作为新增组。
- 旧9题复用v7冻结的题面及参考资料，以免把输入变化当作模型改进；新增11题使用公开原题技术内容的独立重述。模型不接收平台、链接、原题标题、平台评级、旧模型评分、人工目标分或审核意见。
- 匿名随机顺序在首次冻结时生成，断点重跑保持顺序。题目不直接导入正式库，本次不改变原审核。
- 模型先完成20题，再将完整预测与调用记录封存在工作区之外；公开输入/预测的SHA-256承诺。人工表只有匿名编号、原始链接、空难度，不含隐藏预测。
- 9题曾参与开发反馈，公开链接也可能显示平台评级，因此不是严格双盲；将9题回归、11题新增和全部20题分开统计。请人工独立按项目标尺评分，尽量避开原站评级与题解。

## 过程固定

保持请求模型名deepseek-chat作对照，并记录每次响应实际model、用量、耗时、可见结构化输出、修复次数；历史别名不等于精确底层版本恒定。不改环境密钥或公共配置。

v8实际两阶段：先解题并验证方法与标签集合，再按知识/建模/正确性证明/实现四个角度整体评分；审查矛盾退回解法阶段。结构失败最多修复一次，实质审查最多退回一次；失败保留，不人为补分或按目标改结果。置信度为未校准自报，不表示实际正确率。

提示词、实现、词表、端点、请求模型、参数和题面均冻结指纹。中断可复用原样成功断点，只重试失败项，保留失败记录。完整20题后封存；封存后禁止继续重抽模型结果。公开承诺后不更改评分流程来优化本次结果。

## 人工评分与比较

人工仅填难度，100–3500、100整数倍；700及以下沿用语法标尺，800以上沿用项目算法八档。新增样本刻意以算法题为主，不用平台同名分数替代本项目教学标尺。

必须收到完整20题、编号和URL一致的人工表后才能揭盲。保留原始提交文件哈希，逐题记录模型分、人工分、有向差`模型−人工`、绝对差。

全部20题、回归9题、新增11题分别计算：平均绝对误差MAE、中位绝对误差、有向平均偏差、绝对差≤100/200/300的比例、最大绝对差。没有人工评分时不生成虚假的零误差、准确率或通过结果。

一次单人20题不能证明生产适用性；不预设未经用户确认的通过线，不把难度误差当标签准确率。人评完成后分析偏低/偏高及错例，再决定下一版本；不得用同20题调好后宣称独立测试提升。后续需学校题与多评分者独立验证。
