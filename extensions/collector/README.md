# CodePowerPlus 采集助手 0.4.7（开发预览）

Chrome/Edge Manifest V3。平台登录态和密码留在日常浏览器profile；不读取cookie值，不要求贴cookie。服务器仅接收用户明确选择的记录和源码。

## 安装与开始

1. 打开Edge扩展管理页，开启“开发人员模式”，选择“加载解压缩的扩展”，目录选本文件所在的collector文件夹。Chrome同理。这是开发验收入口，千人分发将使用正式商店包。
2. 在同一浏览器profile中打开对应OJ、正常登录本人账号，保持标签页打开。
3. 点击扩展图标打开任务页，选择平台→“授权并识别账号”→选择是否取源码→“开始采集”。AtCoder仅快速模式：授权向AtCoder Problems查询公开账号的副本提交（含练习），批量元数据、官网源码。旧扫描任务先暂停，再点“改用快速采集”；已有记录和源码保留。
4. 查看任务与本地结果，暂停/恢复；重新同步从头回扫并按提交ID更新，不重复本地记录。浏览器关闭后下次打开可继续。重新识别账号后可恢复到新的站点标签页。
5. 任务结束或暂停后，“导出全部JSON”先选择保存位置，再从本地数据库每次读取最多25条并写入文件；上传需先预览、勾选同意，填写本站服务器地址及短期导入令牌。
6. 多余任务可点“删除本地任务”，确认后停止该任务并清除它的本地记录、源码及上传断点，无法撤销；不影响其他任务、服务器数据和已导出文件。未备份的数据先导出。
7. 看到服务器确认接收完成，或打开导出JSON核对记录数与源码后，可以卸载扩展。卸载会删除扩展IndexedDB里的记录和断点，不影响已上传数据及独立保存的文件；以后同步需要重装。仅看到本地预览不能卸载。

## 当前能力与验收边界

- 已实现：四站同源页面适配、识别本人、逐页及逐条源码、IndexedDB原子断点/去重、串行限速/退避、暂停/恢复/回扫、分批读取的流式JSON导出、明确授权上传。
- 0.4.7修复“重新同步”与多任务页同时操作可能使同平台两个任务同时采集的问题；开始、继续、重新同步及旧AtCoder切换均在同一本地事务内检查平台占用，已有任务和断点不受影响。
- 结果预览只读取提交数和最近50条记录；导出按最多25条读取并写入文件，优先使用系统保存文件窗口。浏览器不支持该窗口时使用下载回退。IndexedDB schema v3新增提交时间索引，升级保留已有任务、记录和上传断点。
- 上传计划按25条小页生成，仅持久化批次ID/区间/摘要；上传每次只读取当前批次。数据变化时阻断错续，上传或导出期间禁止本页重新同步/切换操作，其他页面修改任务会被版本及摘要检查拦截。旧版上传计划仍可继续。
- 0.4.1起区分明确验证页与无验证特征的403拒绝；失败时显示阶段、HTTP状态和不含查询参数的路径。遇阻塞先检查该地址，再点“继续”重试断点；不要反复“重新同步”从头回扫。旧任务需重试一次才有新诊断。
- 0.4.2起按当前VJudge本人账号下拉框读取个人资料链接，兼容旧版导航。AtCoder的官网逐比赛适配自0.4.6起已移除。
- 0.4.3起提交时间统一按UTC+8显示，表头明确时区，不随设备时区变化；存储、上传和导出仍保留带时区的标准UTC时间，已有记录无需重采。
- 0.4.5修复洛谷数字状态0（Waiting）被误判为字段缺失、在列表HTTP200时暂停的问题；状态按原值字符串保存，空值/异常结构仍暂停。覆盖原目录更新后重新加载扩展、重开任务页，点“继续”即可从断点恢复，不需重新同步或卸载。
- 0.4.4新增AtCoder快速模式：不以参赛/评级历史限定范围，AtCoder Problems每次最多500条元数据，源码只从官网登录标签页获取；副本调用`credentials:omit`，不发送OJcookie/密码。副本可能滞后/漏收，完成仍只代表副本范围，导出/上传保留来源且coverage不标官网全量。无内存字段时保留null，不伪造0。
- 每个快速任务固定截止时间，前后计数对账；满页末秒计数匹配后才推进，发现截断或变化就暂停而不静默跳秒。旧AtCoder任务先暂停，再点“改用快速采集”授权即可，已有本地记录保留；任务可能混有此前官网记录，导出说明会标注。
- 删除与采集提交事务串行；在途响应不会复活已删除任务，迟到的重同步或上传断点保存也不能重建它。已发出的单次请求可能仍完成，但删除后不再持久化该任务。
- CF与VJudge记录已有历史真实匿名字段依据；洛谷登录态record结构和各站账号选择器仍是开发预览适配。合成DOM覆盖了四站正常/异常路径，不等于真实四站端到端已验收。
- 已在独立Chromium实际加载MV3；用明确合成的CF站点响应验证后台→页面同源请求→源码→IndexedDB→导出，不接触用户Edge profile/真实账号。
- 0.4.6移除AtCoder逐比赛列表扫描和比赛编号入口。旧扫描任务在下次执行前本地暂停，不再发扫描请求；需点“改用快速采集”授权后保留同一任务数据并重建快速断点。副本异常暂停，不自动回退扫描；完成只代表副本范围，不保证官网全量。
- “可见范围已遍历”只说明适配器确认了当前分页终止；动态offset漂移、已隐藏或已删除记录无法由空页证明不存在。首版“重新同步”是全回扫，不是高效原生增量协议。
- 源码缺权限/仅图片/不可用分开记录；WAF/账号变化/解析变化暂停，不解验证码，不提交评测、不改公开状态、不重新评测。
- 元数据保留平台原始verdict/语言（洛谷可能为枚举数字字符串），没有把它们强行变成本项目评分证据；源码和结果缺失不伪造为0。

## 上传服务

应用加载了/api/collection/batches和/api/collection/submissions；默认无服务器secret时503禁用。管理员从环境配置CODEPOWERPLUS_COLLECTION_SECRET（至少32字符）和可选CODEPOWERPLUS_COLLECTION_DB（默认独立data/collection.db，禁止正式学习库路径）。不要把secret提交仓库。

服务器可填写任意 HTTPS 地址，因此清单声明了可选 HTTPS 来源；安装时不授予该权限，只有点击上传时才按输入地址请求单一 origin。跨域扩展上传时，服务端需将扩展 Origin（例如 `chrome-extension://<扩展ID>` 或 `edge-extension://<扩展ID>`）加入 `CODEPOWERPLUS_COLLECTION_ALLOWED_ORIGINS`，多个来源用逗号分隔；本地回环HTTP不需要扩展 Origin 白名单。

管理员在线下用项目Python运行scripts/mint_collection_token.py --user 本站学习者ID --platform codeforces --account 外站账号，签发15分钟token，按平台账号隔离。通过现有可信渠道交给学生；首版没有公开签发端点或学校SSO，不可将现有local-single-user应用直接当千人线上认证系统。

服务端接受协议1的严格字段、一次最多100条/8MB；扩展默认每批最多25条或1.5MB，遇较大源码自动缩小批次，单条超过限制时明确报错。每批唯一ID与下一个批次游标保存在本地IndexedDB；服务端确认后才前移，超时重试使用同一ID，关闭页面/浏览器后可重新输入短期令牌继续。令牌不会持久化。可清除本地上传断点，但不会删除服务器已确认的数据。

独立SQLite schema v2保存规范化提交、按用户SHA-256去重的源码、无源码的观察及批次收据、用户用量计数。四站合计默认120 MiB提醒、150 MiB硬限额（逻辑字节）；超限整批回滚，扩展保留断点并提示空间不足。可通过CODEPOWERPLUS_COLLECTION_WARNING_BYTES / CODEPOWERPLUS_COLLECTION_LIMIT_BYTES调整。

GET `/api/collection/storage`查询本人四站用量；按账号删除需管理员用`--purpose manage`单独签发短期管理令牌，再调用DELETE `/api/collection/submissions?confirm=delete-account-data`，普通导入令牌无权删除。备份恢复及计量口径见`docs/collection-storage-design-2026-10-21.md`。

平台账号归属是本地采集声明，未做独立认证。采集数据不会自动增加题目、标签、分析或画像证据。

## 开发检查

运行 npm ci、npm test；浏览器集成脚本 node tests/browser-check.mjs、node tests/worker-check.mjs、node tests/adapter-check.mjs。脚本用本地安装的Chromium或环境变量COLLECTOR_CHROMIUM_EXECUTABLE指定。测试全为隔离/合成，真实账号验收应单独记录。

打包：用项目Python运行scripts/package_collector.py，生成与manifest版本对应的ZIP（当前为`output/collector/codepowerplus-collector-0.4.7.zip`）；只含manifest/页面/CSS/src/说明，不带node_modules/测试/会话/令牌。未上架Chrome/Edge商店。
